# 浏览器扩展发布准备与检查清单

*发布清单 · 2026-11-11*

本文集中记录 Eim 浏览器扩展发布前需要完成的部署、权限、安全、隐私和验收工作。扩展功能与账号/收藏技术方案见[插件状态、账号与收藏笔记技术方案](../插件账号收藏与笔记技术方案.md)。

## 当前状态

**当前不可直接发布给真实用户。** 生产 API 地址及 host permission 已配置，但插件—服务端—网页登录完整链路和发布要求仍需验收。

代码现状：

- 开发版可在弹窗切换 `http://localhost:4000`、`https://eim.s` 和 `https://eim.fly.dev`；正式版可切换两个 HTTPS 环境，首次使用默认选择 `https://eim.s`。
- 开发版声明上述三个 API host permission，正式版仅声明两个 HTTPS 站点。凭据按 origin 分开保存；旧版没有来源标记的凭据会被清除，需要重新授权。
- WXT 开发模式打开 localhost；生产配置指向 `https://eim.s`。
- 扩展已包含 `storage` 和 `identity` 权限。生产发布前应核对权限确实对应当前功能，并在商店说明用途。

## 发布阻塞项

### 1. 确定生产环境和 API origin

- [x] 配置正式 Web/API origin 为 `https://eim.fly.dev`；仍需验证部署和 HTTPS。
- [ ] 确认两个 HTTPS origin 均提供以下当前依赖的 endpoint：
  - `GET /api/dict/lookup`
  - `GET /api/open_api`
  - `GET /extension/authorize`
  - `POST /api/extension/token`
  - `GET /api/extension/me`
  - `DELETE /api/extension/session`
  - `GET /api/vocab/entries`
  - `POST /api/vocab/entries`
- [x] 将生产 API origin 配置注入扩展生产构建；不得以静默回退到其他站点或空成功响应代替配置错误。
- [x] 将生产构建的 `webExt.startUrls` 从临时的 GitHub 地址改为 Eim 本地生产站点。
- [ ] 验证 `/extension/authorize` 的 Chrome Identity callback 校验、PKCE、state 和生产域名行为。

### 2. 配置最小化 host permissions

- [x] 开发构建允许三个明确的开发和测试环境，不允许任意站点。
- [ ] 生产 manifest 仅允许访问两个 HTTPS API origin；不包含 localhost、通配符域名或无关站点。
- [ ] 检查 `storage` 和 `identity` 权限用途与实际实现一致，并准备面向商店审核的权限说明。
- [ ] 检查生产 build/zip 生成的 manifest，而不只检查源配置。
- [ ] 确认 content script 不需要新增对任意网页 host 的权限；网页读取与 API 请求的权限边界保持清晰。

### 3. 认证与凭据安全

- [ ] 继续使用网页登录 + 一次性授权码 + PKCE；扩展不收集 Eim 密码。
- [ ] API key 只存放在扩展 trusted context 可访问的 extension storage，由 background 读取和发送；不得放进网页 DOM、content script 消息、URL、日志或同步存储。
- [ ] 浏览器端确认授权码和 verifier 只通过预期流程传递，授权码不可重放；页面错误、用户取消、服务端拒绝均显示明确状态。
- [ ] 覆盖 API key 过期/撤销、退出后清除本地凭据、服务端暂时不可用和重新连接流程。
- [ ] 当前 API key 有效期为 30 天。上线前确认此期限、撤销体验和多设备行为符合预期；后续如需轮换或缩短期限，另行设计迁移策略。
- [ ] 对 token 兑换、API key 创建和认证失败配置适当的速率限制及滥用防护。

## 网络与 CORS

- 扩展请求由 MV3 background service worker 发起，并使用 manifest host permission；不要为了扩展 background 请求而默认给 Phoenix API 开启宽泛 CORS。
- 若以后改为网页上下文直接请求 API，重新评估 CORS，并仅允许实际需要的 origin、方法和请求头。
- 所有生产认证和用户数据请求必须经 HTTPS；不得在生产环境允许明文 HTTP API origin。
- 对网络超时、非成功状态码、无效响应和断网提供明确 UX；错误不能表现为查询/收藏成功。

## 隐私与商店信息

- [ ] 发布前提供可访问的隐私说明，解释扩展收集/处理的数据、用途、保存位置、保留期限和删除方式。
- [ ] 明确说明：选中的词/短语会发送到 Eim 词典 API；用户主动收藏时词条、释义快照及可选 note 会关联其账号并存储在服务端。
- [ ] 说明插件 API key 用于认证、由扩展本地保存且可通过退出登录撤销；不收集网页整页内容。
- [ ] 确定用户请求删除账号时，服务端收藏、API key 和其他相关数据的删除策略。
- [ ] 准备商店描述、支持联系渠道、隐私政策 URL、截图和图标，并确保描述与实际权限/数据流一致。
- [ ] 确认扩展名称、描述和 `extension/package.json` 中的发布元数据，不沿用 starter 名称或占位信息。

## 发布前自动化检查

在 `extension/` 目录执行：

```sh
bun run check
bun test
bun run build
bun run zip
```

逐项确认：

- [ ] 类型检查和生产构建通过。
- [ ] zip 中的 manifest 指向正确的 production API host permission，不含 localhost。
- [ ] 生产 bundle 不允许 localhost 环境，且没有调试凭据、测试账号或临时站点配置。
- [ ] 生产启动页指向 `https://eim.s`，或已按产品决策移除。
- [ ] 权限、站点域名和隐私说明相互一致。

## 浏览器端到端验收

在干净的 Chrome 配置文件中安装生产 zip，并连接已部署的生产服务：

- [ ] 首次安装、popup 打开和划词开关状态持久化正常。
- [ ] 两个 HTTPS 环境均可切换，重启后保留选择，账号和收藏按环境隔离。
- [ ] API 在线/离线状态正确；服务未配置时明确显示未配置，而不是冒充在线。
- [ ] 未登录时可公开查词，收藏操作引导登录。
- [ ] 登录、用户确认、Chrome Identity callback、PKCE code 兑换和用户身份显示完整成功。
- [ ] 收藏命中词条并附加可选 note；重复收藏保持幂等且不覆盖既有 note。
- [ ] 打开 Web `/learn/vocab` 能看到同一账号收藏；网页和插件的登录态各自独立，行为符合产品说明。
- [ ] 退出扩展账号后本地凭据清除且服务端 API key 撤销；重新查词仍可用，收藏需重新登录。
- [ ] 过期凭据、取消授权、断网、超时、401/403 和服务端错误均显示可理解状态，不丢失可重试输入。
- [ ] 页面输入框、复杂网页、连续快速选词、Shadow DOM 交互和浏览器重启后行为无明显问题。

## 发布记录

每次发布建议记录：

- 版本号与构建 commit。
- 生产 Web/API origin 及部署版本。
- 生成的 manifest 权限审查结果。
- 自动化检查和浏览器端验收结果。
- 商店提交/审核状态和回滚方式。

不要在发布记录中保存 API key、授权码、用户 note 或其他凭据/个人数据。
