# 划词采集优化方案

> 状态：需求与技术方案参考，供后续拆分实施；当前仅记录已选词条，不采集网页来源或上下文。  
> 相关文档：[插件账号、收藏与笔记技术方案](./插件账号收藏与笔记.md)、[插件划词查词 MVP](./插件划词查词MVP.md)。

## 1. 背景与目标

划词收藏目前保存词条、词典释义快照及用户可选笔记，但没有记录该词来自哪个网页或原文语境。稍后复习时，用户可能只记得词条，却忘了它为何重要、在原文中是什么意思。

本方案为每次收藏补充可追溯的采集上下文：

- 来源页面：标题、规范化网址和采集时间。
- 原文上下文：包含选中文字的段落或适当长度的周边文字。
- 采集控制：用户能预览、修改或关闭上下文采集，并理解将保存哪些信息。

设计原则：

- 收藏动作仍由用户明确触发；查词不等于同意保存页面信息。
- 只采集理解该词所需的最小文本，不抓取整页、截图或无关 DOM。
- 采集数据属于用户的私人学习资料，不写入公共词典或分享给其他用户。
- 页面来源和上下文应保留在来源记录中，不与释义快照或用户 note 混为一谈。
- 对用户可见、可编辑、可删除；来源不完整时仍能正常收藏。

## 2. 产品需求

### 收藏前

- 选中文字后继续沿用现有查词弹窗流程，不因上下文读取阻塞词典查询。
- 弹窗在收藏区域提供“来源与上下文”预览；来源 URL 和段落采集可通过设置关闭。
- 清楚区分“当前查词选区”和“自动提取的原文上下文”。默认上下文包含所选文本，长度有限，可编辑。
- 收藏前允许用户移除上下文或修改自动提取结果；显式点击收藏后才上传。
- 当前页面无法安全或可靠读取上下文时，退化为只收藏词条并明确告知，不影响查词。

### 已收藏后

- 学习中心词条详情按时间展示来源记录，可从记录跳回来源页面（若 URL 可用）。
- 同一词条可来自多个页面或多次采集；每条来源记录展示采集时间、页面标题/链接和上下文。
- 编辑或删除个人来源记录不改变公共词典释义；删除词条时按产品定义一并删除其私有采集记录。
- 不覆盖用户手动笔记；上下文与 note 是不同字段和用途。

### 设置与控制

- 提供全局开关控制是否采集来源 URL 和上下文，并在收藏弹窗内允许单次关闭。
- 可选的后续能力：按域名排除采集、查看/导出/删除采集数据。
- 敏感或不可读取页面（浏览器内部页面、扩展页面、受限页面）不采集来源内容。

## 3. 上下文提取建议

### MVP 抽取规则

1. 从浏览器 `Selection` 获取实际选区和 Range，不通过整页 `innerText` 搜索所选文本。
2. 选区文本仍是当前查词文本；上下文优先使用包含该 Range 的最小语义块，例如 `p`、`li`、`blockquote`，再逐级向外寻找合理块级容器。
3. 清理多余空白和控制字符，确保提取结果包含选区；对上下文设定长度上限，超长时保留选区附近片段并用省略号标示。
4. 若页面结构无法识别，回退到有限长度的选区前后文；不可读时留空，不猜测、不遍历整页。
5. 不从输入框、文本域、密码框、可编辑区域或用户主动编辑的内容中自动提取上下文；这类选区可只进行查词。

上下文上限应通过真实页面验收后确定。初版可将最长上下文控制在约 1,000 个字符以内，并对请求体再次设置总长度限制。长度限制是保护措施，不代表需要采满上限。

### 来源 URL 规范化

- 采集页面 `origin`、`pathname` 和 `document.title`。
- 默认去除 fragment；默认不保存 query string，避免意外记录搜索词、邮箱、会话标识或一次性 token。
- 若产品确需保留 URL 参数，必须去除常见凭据字段（如 `token`、`code`、`key`、`password`、`auth`），并在收藏前提供可见预览和编辑/清除入口。
- `javascript:`、`data:`、`file:`、浏览器内部地址及不安全/无效 URL 不保存为可跳转链接。
- 来源页面标题和 URL 都视为用户数据；需要按与上下文相同的授权、保留、删除和隐私政策处理。

## 4. 页面体验框架

### 插件划词弹窗

- 保留主要查词内容优先级，来源信息放在收藏区域的紧凑、可折叠分区，避免遮挡释义。
- 默认提供一段简短上下文预览，并标识所选词；提供编辑/移除操作。
- 页面标题与来源域名可简短展示，完整规范化 URL 放在可展开或可复制区域。
- 收藏按钮文案和处理中状态保持明确；上传失败时保留用户编辑的上下文，允许重试。
- 用户关闭采集或没有可用上下文时，收藏请求仍可成功。

### Web 学习中心

- 词条详情分区：词典释义、个人笔记、采集来源/语境、收录信息。
- 来源记录按时间倒序展示；多次采集时各记录相互独立，不拼成一段无法追溯的文本。
- 小屏使用折叠区域，避免来源段落挤压首屏词条内容。
- 空来源不展示空白卡片；链接不可用时仍显示来源标题和采集文本。

## 5. 数据模型建议

不建议将 `source_url` 和单个 `context` 长期直接塞进 `Eim.Vocab.Entry`：

- 用户可能在多个页面再次遇到同一词条。
- 当前词条按 owner + term key 幂等去重；重复收藏不会创建新词条，若上下文直接放在词条上就会面临覆盖、丢失历史或复杂合并规则。
- 一个词条对应多个采集来源是自然的一对多关系。

建议在阶段性演进中新增私有的采集记录资源，例如 `Eim.Vocab.Capture`：

| 字段 | 说明 |
| --- | --- |
| `id` | UUID 主键 |
| `entry_id` | 关联用户自己的 `Eim.Vocab.Entry` |
| `source_url` | 规范化后可选 URL |
| `source_title` | 可选页面标题 |
| `context_text` | 可选、限长的纯文本上下文 |
| `selected_text` | 可选，用户实际划选文本；如已能从词条 lookup 信息还原，可评估是否重复保存 |
| `captured_at` | 用户触发收藏的时间 |
| `inserted_at` / `updated_at` | 系统时间戳 |

必须通过父词条 owner policy 或等价校验，确保采集记录只能由词条 owner 读取、更新和删除；客户端提供的 `entry_id` 不能作为授权依据。

### 重复采集策略

默认保留一条词条和多条采集记录：

- 同一条目在相同页面短时间重复提交可幂等去重，避免双击产生重复来源。
- 在不同页面或明显不同上下文重新收藏，新增一条 Capture，不覆盖已有 note 或旧上下文。
- URL、标题或上下文为空时允许保存；不得为了来源信息而阻断正常收藏。
- 收藏条目创建与采集记录写入应有清晰的一致性策略；优先在同一服务端事务中完成，避免出现已显示收藏成功但采集记录丢失。

如果第一版只需要单一上下文，也应先明确这是临时折中；不应让隐式“最后一次覆盖”成为未定义行为。

## 6. 插件与服务端边界

### Content Script

- 只从当前 Selection/Range 附近读取有限、可见的纯文本及当前页面元信息。
- 采集逻辑在 Shadow DOM 浮层内部排除，不能把弹窗自身内容当作网页上下文。
- 不读取页面 Cookie、localStorage、表单值、密码、脚本状态或隐藏内容。
- 通过显式收藏消息将查词结果、用户确认后的来源元信息和上下文传给 Background。

### Background

- 继续作为唯一网络请求层，校验消息 shape、字段类型、协议、URL 和文本上限。
- 不把页面传来的 URL 当作任意 fetch 目标；只将采集数据作为受限 JSON payload 发往固定 API base URL。
- 超时、HTTP 错误、认证失效和响应校验遵循现有收藏请求模式；失败时向浮层返回明确错误，不伪装成保存成功。

### API 与 Ash

- 为收藏创建能力增加可选来源/上下文字段，或提供原子创建词条及 Capture 的服务端 action。
- 幂等创建词条时区分“词条已存在”和“新采集已记录”；不覆盖既有用户 note。
- 定义只允许 owner 操作 Capture 的读取、编辑和删除能力；不开放公共词典 API 修改这些字段。
- 请求及响应均校验 URL scheme、长度、文本长度和可空行为；输出按纯文本安全渲染。
- 评估 Capture API 的幂等键，以支持网络重试且不重复写入。

## 7. 隐私、安全与数据治理

- 上下文可能包含版权文本、私密网页内容、个人信息或内部资料。默认只在用户点击收藏时上传，不因划词查询自动保存。
- 对用户明确展示“将保存来源页面及选区附近文字”，提供关闭和编辑入口；设置变更即时生效。
- 不记录整页内容、DOM 快照、截图、Cookie、认证头、页面脚本或不可见文本。
- 提供清除单条采集上下文的能力；用户删除词条或账号时按保留策略删除关联数据。
- 上下文与 URL 不写入遥测、普通日志或错误追踪。错误日志只记失败类别和请求 ID，不输出正文或完整 URL。
- 服务器端限制字段大小和请求总量，防止恶意页面或客户端伪造超大负载。
- 来源链接仅以普通锚点跳转，不在服务端自动请求该 URL，避免 SSRF 和对第三方站点的无意访问。
- 在公开发布前确定隐私告知、保存期限、数据导出/删除流程及对版权内容的处理原则。

## 8. 验收标准

- 仅查词不会上传或持久化网页上下文；明确收藏后才可能保存。
- 上下文预览包含用户选区、长度有限、纯文本呈现，并能在收藏前编辑或移除。
- 受限页面、表单/可编辑区域或无法识别的选区不会导致整页内容被采集。
- 来源 URL 不含 fragment；默认不含 query string；不安全 scheme 不生成可跳转链接。
- 收藏失败时输入内容保留且用户可重试；上下文缺失不阻塞词条收藏。
- 同一词条在多处采集不会覆盖旧上下文或个人 note；重复提交行为有明确去重规则。
- 用户只能访问、修改和删除自己的采集记录；其他 owner 的条目及来源内容不泄露。
- 删除词条时关联采集记录按约定处理；服务端和扩展均对超长输入做验证。
- 覆盖扩展类型检查、构建、API owner policy、幂等重试、受限 URL 和上下文边界测试。

## 9. 分阶段实施

1. **定义隐私默认值**：决定 URL/query 处理、采集开关、域名排除和上下文长度。
2. **插件预览原型**：在本地提取 Selection 周边文本并提供预览/编辑/关闭；尚不上传。
3. **Capture 数据与 API**：实现一对多采集记录、owner policy、事务和幂等行为。
4. **收藏流程接入**：显式确认后随收藏请求提交来源信息；验证失败与重试体验。
5. **学习中心呈现**：在词条详情中按时间显示多个来源上下文并支持删除。
6. **隐私与发布验收**：测试真实站点、受限页面、页面动态内容、隐私政策和数据删除。

## 10. 待确认问题

1. 是否默认开启自动上下文预览，但收藏前可关闭；还是默认关闭、由用户主动展开？
2. 来源 URL 是否只存 origin + pathname，还是在用户确认后保留经清洗的 query 参数？
3. 是否需要支持域名级排除规则，设置范围为全局还是同步到账户？
4. 选中的文本是否作为 Capture 独立字段保存，还是复用词条已有的 `lookup_text`？
5. 同一词条多次采集的最短去重窗口和重复判定依据是什么？
6. 用户删除收藏词条时，是否永久级联删除所有来源记录，还是将来支持保留在个人历史中？
