# 插件状态、账号与收藏笔记技术方案

*方案 · 2026-11-11 · 分阶段交付*

**命名约定：**本文将 `Vocabulary` 简写为 `Vocab`，与 `Dictionary` 简写为 `Dict` 的命名风格一致。因此，词汇收藏领域、模块分别命名为 `Eim.Vocab`、`Eim.Vocab.Entry`，API 路径使用 `/api/vocab/...`。

## 1. 背景与目标

扩展已提供划词查词、设置、账号连接和首版收藏能力。后续目标是继续完善学习中心，让用户能管理收藏、检索词条并复习。

目标是让扩展从“自动查词工具”渐进演进为与 Eim Web 学习中心连接的入口：

1. 用户能看到扩展启用状态并暂停/恢复自动查词。
2. 用户能理解当前 API 连接状态并进入 Eim 登录流程。
3. 已认证用户能收藏查到的词条、添加和编辑个人笔记。
4. 学习中心后续能查看、检索和复习已收藏内容。

设计原则：扩展只保存必要的认证凭据；账号数据由服务端授权和持久化；词典结果与用户自定义笔记分开；每阶段可独立交付和验证。

## 2. 当前基础与限制

- 扩展使用 WXT + Svelte，MV3 background service worker 和 Shadow DOM 浮层。
- 已有 `GET /api/dict/lookup?text=...`，浮层自动显示 ECDICT 查词结果。
- Phoenix 已有 AshAuthentication 账号、Bearer token/API key 基础设施。
- `GET /api/dict/lookup` 仍为公开查询；扩展账号认证及阶段 3 收藏能力已实现初版。
- 插件生产发布准备（生产 API、host permissions、安全、隐私和浏览器验收）单独维护于[扩展发布准备与检查清单](./extension/发布准备与检查清单.md)。
- web 登录页面与 extension sign-in 并不天然共享认证状态；仅打开网页登录页不能认为扩展已经登录。

## 3. 分阶段范围

### 阶段 1：扩展状态与设置（已实现初版）

**交付**

- 将 popup 替换为 Eim 扩展面板，显示产品名称、划词开关、API 连接状态。
- 开关状态写入 `browser.storage.local`，默认开启，重启浏览器后保留。
- Content script 监听设置变更；关闭时不自动查询并收起已有结果。
- popup 提供连接 Eim 账号的入口。
- 开发版提供 localhost 服务状态检查；API 未配置时显示“尚未配置”。
- 页面浮层监听开关变化，暂停时关闭浮层；background 同时检查持久化开关，阻止暂停状态下的查询请求。

**验收**

- popup 中开关可立即生效；重开 popup 和浏览器后状态一致。
- API 不可用时显示离线，不影响 popup 正常使用。
- 关闭后选词不发 API 请求。

**当前实现说明**

- Popup 已替换默认 WXT/Svelte 脚手架界面，展示开关、词典服务状态和账号连接状态。
- `lookupEnabled` 存在 `browser.storage.local`，首次安装默认为启用。
- 连接状态通过 Background 请求 `/api/open_api` 探测；该检查只代表服务可连接，不代表用户已认证。
- popup 使用 Chrome Identity 打开网页登录授权流程；授权成功后由 background 保存 API key 并查询当前账号。划词弹窗可收藏词条并附加可选笔记。
- 已用 `bun run check` 和开发/生产构建验证类型及 manifest；浏览器完整链路与生产发布验收参见[扩展发布准备与检查清单](./extension/发布准备与检查清单.md)。

### 阶段 2：扩展账号认证（已实现初版）

**推荐路线：网页登录 + 一次性授权码交换**

1. 扩展通过系统浏览器打开 Eim 网站的“连接扩展”登录页面。
2. 用户使用现有网页认证登录并确认连接。
3. 服务端生成 5 分钟有效、单次使用并绑定 PKCE challenge 的授权码，通过 Chrome Identity callback 的 URL fragment 返回。
4. 扩展 background 使用授权码和 verifier 交换 30 天有效的 Ash API key；API key 由服务端哈希存储。
5. popup 显示登录用户；退出登录时撤销服务端凭据并清除本地凭据。

**当前实现说明**

- `GET /extension/authorize` 校验 `chromiumapp.org` 回调、PKCE challenge 和 state；网页登录成功后签发授权码。
- `POST /api/extension/token` 原子消费授权码并返回 API key、key id、过期时间和用户信息。
- `GET /api/extension/me` 返回当前账号；`DELETE /api/extension/session` 撤销当前用户的指定 API key。
- 插件 API key 仅保存在 extension local storage 的 trusted contexts 中，由 background 发起认证请求；popup 仅展示身份和触发连接/退出。
- 已覆盖网页登录回跳、错误/重放授权码、API key 认证与撤销的 controller 测试。
- 当前采用 30 天 API key，而非短期/可轮换凭据；后续可在确定生产部署和多设备策略后再设计轮换。

**安全要求**

- 不在插件中收集或长期保存用户密码。
- 不通过可被网页脚本读取的 query 参数传长期 token。
- 授权码应短时、单次、抗重放；扩展 callback 和 client 标识需校验。
- API 凭据存储使用浏览器扩展存储 API，绝不写入页面 DOM、日志或同步存储。
- 确认凭据撤销、过期、轮换与多设备行为。
- 登录界面应说明哪些数据会与账号同步。

**备选方案**

- 直接在扩展内输入邮箱密码：实现容易，但扩大凭据暴露面，不推荐。
- 让扩展依赖网页登录 cookie：跨域、浏览器权限与生命周期耦合强，不作为默认路线。

### 阶段 3：划词弹窗收藏与可选笔记（已实现初版）

#### 需求定义

**目标与前置条件**

- 用户已在插件中连接 Eim 账号；网页 session 与插件账号独立，收藏身份以插件 API key 对应的账号为准。
- 未登录用户仍可正常查词，但不能收藏。弹窗提供“登录后收藏”入口，完成连接后可重新执行收藏。
- 仅词典命中结果可收藏；未命中、查词失败或仍在加载时不展示可用的收藏操作。

**用户故事**

1. 已登录用户可以直接从划词释义弹窗收藏当前词条，不离开阅读页面。
2. 用户可以在收藏时添加可选笔记，也可以不写笔记直接收藏。
3. 再次查到已收藏词条时，弹窗展示已收藏状态，不创建重复记录。
4. 操作失败时用户能看到失败状态并重试；系统不把失败伪装成成功。

**弹窗交互与状态**

- 命中结果展示“收藏”按钮；已收藏时显示“已收藏”状态。未登录时使用“登录后收藏”引导。
- 收藏按钮提交后进入处理中状态并防止重复点击；成功后即时更新为已收藏。
- 笔记输入为可选、默认收起的轻量区域，设置字符上限并显示校验错误。本阶段收藏后不在浮层编辑笔记，后续由学习中心提供编辑能力。
- 登录成功后可重新查词或重新打开弹窗刷新收藏状态；收藏状态从服务端读取，不只依赖本地缓存。
- token 过期时清除本地凭据并提示重新连接；服务不可用或请求失败时保留笔记输入并允许重试。
- 取消收藏和离线收藏不在本阶段范围内。

**服务端数据与授权**

- 新增独立的 `Eim.Vocab` 领域和收藏资源 `Eim.Vocab.Entry`；不将用户笔记写入共享的 `Eim.Dict` 词典数据。
- 记录 owner、规范化词条键、首次查询文本、lemma、必要的释义快照、可空 note 和时间戳。保存快照可避免词典数据变化后用户收藏内容不可解释。
- 推荐用非空 lemma 作为去重词条，否则使用查询文本；服务端统一 trim、Unicode 规范化并按不区分大小写的形式生成唯一键。保留首次查询文本用于展示。实现前确认词形及短语的合并预期。
- 数据库唯一约束为 owner + 规范化词条键，以处理并发重复收藏；重复提交返回已有条目，且不能覆盖用户已有笔记。
- owner 只能从已认证 actor 推导，不接受客户端传入的 owner ID。私有读取和写入应用 Ash owner policy；唯一约束负责并发正确性。
- 笔记按纯文本存储并限制最大长度；网页输出使用正常文本转义，不将用户输入当作 HTML。

**当前实现说明**

- 新增 `Eim.Vocab.Entry` 与数据库迁移，term key 由服务端按非空 lemma（否则 lookup text）执行 NFKC、trim、lowercase 生成。
- 使用 owner + term key 唯一约束及不更新冲突字段的 upsert；重复收藏返回已有收藏，不覆盖既有笔记。
- `POST /api/vocab/entries` 和 `GET /api/vocab/entries` 由必须提供 API key 的路由提供；Ash policy 只允许当前用户创建和读取自己的记录。
- 词典释义快照以 JSON map 保存；note 最多 2,000 字符。
- Background 独占 API key 读取、收藏状态查询和创建请求；内容脚本只通过 runtime message 请求。登录授权也统一由 Background 处理，以便从划词弹窗发起。
- 定向 API 测试覆盖创建/查询、重复提交不覆盖 note、用户隔离、未认证和超长 note。

**API 与扩展端边界**

- `POST /api/vocab/entries`：提交当前 lookup 词条及可选 note，不接收 owner；重复收藏返回已有条目。
- `GET /api/vocab/entries`：分页列出当前用户收藏；支持按规范化 term 查询，用于弹窗获得已收藏状态。
- `PATCH`、`DELETE` 留给学习中心阶段，本阶段不实现。
- API 从 API key actor 获取用户；未认证返回 401，其他用户的收藏不得泄漏其存在性或内容。
- 建议沿用 AshJsonApi；开工时确认 Ash action 与 JSON:API 的幂等冲突返回约定。
- 内容脚本只发送“收藏当前结果”消息给 Background。API key 仅由 Background 从 trusted extension storage 读取并附加到请求，绝不发送到页面或内容脚本。
- Background 负责收藏 API 调用、超时、HTTP 状态分类和凭据失效处理；内容脚本负责呈现状态。
- 发布前的生产 origin、host permission 和网络验证要求见[扩展发布准备与检查清单](./extension/发布准备与检查清单.md)。

**验收标准**

- 未登录用户仍可查词；命中词条显示登录后收藏入口，连接账号后能收藏。
- 已登录用户可收藏命中词条并可填写可选笔记；未命中结果不能收藏。
- 收藏成功后立即显示已收藏；重新查词/打开弹窗后仍显示正确状态。
- 连续点击、并发请求和重复操作最终仅创建一条该用户词条记录，且已有笔记不会被覆盖。
- 401 提示重新连接；网络或服务端错误明确显示失败且可重试。
- 用户不能读取、修改或推断其他用户的收藏；伪造 owner ID 不改变数据归属。
- note 为空可接受；超长输入明确拒绝；note 在网页输出时作为文本转义。
- 自动化测试覆盖未认证、归属隔离、幂等冲突、note 边界；同时验证扩展类型检查、构建和关键弹窗交互。

**领域模型概要**

- 在独立的 `Eim.Vocab` 学习领域增加用户词条资源 `Eim.Vocab.Entry`。
- 每条记录归属一个 user，保存规范化 lemma/term、首次查询文本、必要的词典来源/释义快照、个人 note、创建/更新时间。
- 用用户 ID + 规范化词条建立唯一性，重复收藏应幂等；用户只能读写自己的条目。
- 词典数据仍由 `Eim.Dict` 管理，不将用户笔记写入全局 Lexeme。

**API 路由概要**

- `POST /api/vocab/entries`：收藏词条；重复请求返回已有条目。
- `GET /api/vocab/entries`：分页列出当前用户收藏。
- `PATCH /api/vocab/entries/:id`：阶段 4 仅更新 note。
- `DELETE /api/vocab/entries/:id`：阶段 4 取消收藏。
- 所有写入和用户私有读取都要求 Bearer 认证，并通过 Ash policy 校验 owner。
- 校验 note 长度并对输出做正常文本转义；不接受客户端传入 user_id 作为授权依据。

**扩展交互概要**

- 命中结果显示“收藏”按钮；未命中不显示收藏。
- 收藏时允许填写可选 note；收藏后的笔记编辑留给阶段 4 学习中心。
- 展示收藏中、已收藏、失败重试状态；重复点击不得生成重复记录。
- popup 登录状态用于展示账号连接情况；词条收藏操作发生在划词释义弹窗。

### 阶段 4：Web 学习中心 Vocabulary（已实现初版）

#### 目标与用户身份

- 为登录用户提供个人词汇收藏管理页，可查看、搜索、排序、分页、编辑 note 和删除收藏。
- 页面数据以当前网页登录用户为准；网页 session 与扩展 API key 是独立凭据。浏览器页面不调用 extension token API，也不要求用户先连接扩展。
- 未登录用户访问学习中心时跳转登录；登录后回到原目标页。用户只能操作自己拥有的 `Eim.Vocab.Entry`。
- 本阶段只管理已收藏词条，不实现新词条录入、复习算法、掌握度/学习状态、词单/标签、批量操作或导入导出。

#### 页面入口与路由

- 新增认证页面 `/learn/vocab`，主导航中为已登录用户展示 `Vocabulary` 入口。
- 首页已登录 CTA 指向学习中心；未登录首页继续引导注册/登录。首页的产品介绍内容不替代词条管理页。
- 推荐用 LiveView 实现搜索、分页及逐条编辑后的局部更新；路由放入已有 Ash Authentication LiveSession，并使用 `EimWeb.LiveUserAuth` 的登录保护。页面和 layout 按 Phoenix v1.8 传递所需的 `current_scope` / `current_user` assigns。
- 页面使用 HEEx，并以 `<Layouts.app flash={@flash} ...>` 包裹内容；表单使用 `to_form/2` 与项目已有 `<.input>`，避免另造表单组件。
- LiveView 通过 `Eim.Vocab` / Ash 资源直接查询和执行操作，并将当前网页登录用户作为 actor；不要在服务器端模拟插件请求或把 API key 暴露给浏览器。
- 若项目在实施前仍没有统一的 authenticated LiveView session，先补齐 session/on_mount 配置并覆盖登录重定向测试，再加入学习中心路由。

#### 词条列表与检索

- 默认按最近更新时间倒序，使用稳定次序（`updated_at DESC, id DESC`）；支持按更新时间升序/降序切换，不提供词条字母排序。
- 每页条数可选 10、20、30，默认 10；服务端分页。切换搜索词、排序或每页条数时回到第一页。URL query 保留搜索词、时间排序、每页条数和页码，支持刷新、浏览器前进/后退和分享当前筛选状态。
- 页面整体分为顶部搜索区、主体双栏和底部分页信息区。主体左栏顶部提供排序下拉或未来的列表视图 tabs，下面是紧凑词条列表；右栏整体显示当前词条详情，窄屏改为覆盖层。搜索框使用轻量样式和友好 placeholder，当前命中数在输入框右侧；每页条数、显示范围、总命中数和分页控制统一放在页面底部。
- 排序规则通过下拉选择（如最近更新、最早更新）；列表视图类别（如全部、特别关注）未来增加时使用 tabs，避免把不同含义的操作混在同一控件中。
- 搜索输入 trim 后对 `term_key`、`lookup_text`、`lemma` 做不区分大小写的子串匹配；不搜索释义快照或 note，避免对 JSON 快照和任意文本做高成本模糊查询。空搜索显示全部个人收藏。
- 词条以紧凑等高的单列列表呈现，行内显示主要词形、音标和 note 摘要；选中词条后在右侧详情抽屉分区展示释义、个人 note 和收录信息。窄屏抽屉以覆盖层呈现，避免列表卡片高度随释义数量变化。删除和后续词条级操作集中放在详情抽屉。
- 详情抽屉内展示主要词形（优先 `lemma`，否则 `lookup_text`）、原始查询词（若不同）、音标、快照释义、note 和收录时间（`inserted_at`）；快照缺少可选字段时仍须正常显示词条。
- 释义快照只作为词典结果的历史显示数据，不作为可编辑内容；note 是用户唯一可编辑字段。所有快照和 note 都按纯文本安全渲染，不解释为 HTML。
- 搜索结果不包含其他 owner 的条目；除非必要，不提供能够区分“记录不存在”和“属于其他用户”的错误细节。

#### 笔记编辑与删除

- 详情抽屉内 note 文本框始终可编辑并左对齐，显示字符计数；输入停止后自动保存，失焦时补充保存，不需要额外确认按钮。自动保存只更新对应列表行，不重置列表 stream，也不关闭详情抽屉，以免打断输入和焦点。空 note 是有效值，可用于清除已有 note。
- 编辑态显示明确的已保存状态；保存失败时保留输入并显示错误，允许继续修改后重试。
- note 上限沿用当前资源约束 2,000 字符；提交前后端都校验，超限时保留输入并显示字段级错误，不清空用户输入。
- 保存成功后刷新当前分页并按新的 `updated_at` 位置排序，显示明确成功状态；失败时保留编辑内容并允许重试。没有内容变化时不发更新请求。
- 删除表示永久删除该用户的收藏记录（hard delete），不做软删除或回收站；操作前二次确认，服务端成功后才从列表移除。暂不提供撤销，避免引入回收站和恢复策略。
- 并发编辑采用最后一次成功保存覆盖（last-write-wins）；本阶段不加入版本字段或冲突合并。前端不得在请求失败时呈现成功状态。
- 提供 Vim 风格快捷键：`j`/`k` 在当前页词条间向下/向上移动焦点并立即切换详情；`i` 聚焦当前词条的 note；`/` 聚焦搜索框。通过 `i` 或 `/` 聚焦时，光标放到已有内容末尾，便于接着编辑或追加搜索。页面提供快捷键按钮及 `?` 帮助面板，便于随时查阅。输入框和文本区中忽略 `j`/`k`、`i` 与 `/`，避免影响文本输入；输入框或文本区聚焦时按 `Esc` 会使其失焦（note 失焦时触发保存），帮助面板打开时按 `Esc` 关闭帮助面板。详情使用明确的关闭按钮关闭，不占用 `Esc`。

#### 服务端操作与 API 合约

- 新增受 owner policy 保护的更新 note 与删除 action。更新 action 只接受 `note`，不允许更改 owner、词条键、查询词、释义快照或时间戳；更新时间由数据库/Ash 自动维护，且列表时间排序使用 `updated_at`；删除 action 只允许当前 actor 删除自己的记录。
- 保持扩展 API Bearer/API-key 认证语义不变；为已承诺的通用词条资源补齐：
  - `PATCH /api/vocab/entries/:id`：只更新 `note`，允许传 `null` 清空。
  - `DELETE /api/vocab/entries/:id`：删除当前用户自己的词条。
- Web LiveView 使用同一 Ash resource actions 和 owner policy，直接以网页 session 对应用户作为 actor。不要让浏览器拿到 extension API key，也不要让插件专用 controller 成为 Web 的数据访问层。
- 写入通过 Ash policy 校验 owner；不能仅依赖 UI 隐藏按钮或客户端提交的 ID。对越权请求返回不泄漏资源存在性的结果。
- API 更新和删除须加入统一 OpenAPI 文档；明确更新只允许 `note`，并记录 2,000 字符限制、null 清空语义、未认证和越权行为。

#### 页面状态与 DOM 可测试性

- 页面分别呈现首次空列表、搜索无结果、加载中、加载失败、保存失败和删除失败；空列表提示用户如何通过浏览器扩展收藏第一条词汇，并提供扩展连接/安装指引（若对应链接可用）。
- 搜索无结果提供清除筛选入口；分页边界禁用相应导航操作。
- 关键表单和操作提供稳定唯一 DOM ID，例如 `vocab-search-form`、`vocab-entry-<id>`、`vocab-note-form-<id>` 和 `vocab-delete-<id>`，以便 LiveView 测试。
- 测试使用 `has_element?/2`、`element/2` 等 LiveViewTest selector 验证页面结果，优先检查关键 DOM ID 和操作结果，不绑定易变文案或原始 HTML。
- 收藏列表使用 LiveView stream；note 更新会改变 `updated_at`，因此保存/删除后重新查询并 reset 当前分页 stream，确保排序和分页正确。模板为 stream 容器设置 ID 和 `phx-update="stream"`，并为每个条目使用 stream ID。

#### 安全、隐私与范围外

- 页面仅在有效网页登录 session 下可访问；所有查询和变更均绑定当前 actor。未知 ID、其他用户 ID 和伪造 owner 参数均不能读取、修改或删除他人数据。
- 用户 note 按纯文本处理并遵循已有长度限制；日志和错误信息不得输出 note 全文、API key 或登录凭据。
- 阶段 4 不新增用户词汇内容到共享 `Eim.Dict`；不做跨账号分享。
- 数据导出不在本阶段范围内；扩展发布时的账号数据删除要求见[扩展发布准备与检查清单](./extension/发布准备与检查清单.md)。单条收藏 hard delete 不等于账号注销时的数据清除。

- 未登录用户可使用公开词典查词；可关闭自动划词。
